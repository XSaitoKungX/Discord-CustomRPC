## Project

Discord Custom RPC Manager — a cross-platform Electron desktop app for creating,
managing, and activating custom Discord Rich Presence profiles. Open source (MIT),
free. Current version: `2.0.0`.

## Tech stack

- Electron 41 + React 19 + TypeScript.
- Tailwind CSS v4, Radix UI, shadcn-style components, Lucide icons.
- Zustand for state; `react-router-dom` hash router.
- Main process: `better-sqlite3` + `drizzle-orm`, `discord-rpc`, `electron-updater`.
- Build: `electron-vite` + `electron-builder`. Package manager: **Bun**.

## Commands

- `bun install` — install dependencies.
- `bun run dev` — rebuild native deps then start dev (renderer on port 7000).
- `bun run build:full` — generate migrations + production build.
- `bun run build:win` / `build:linux` / `build:mac` — package per platform.
- `bun run lint` — eslint over `src/`.
- `bun run typecheck` — `tsc --noEmit`.
- `bun run db:generate` / `db:migrate` / `db:studio` — Drizzle workflows.
- `bun run prepare:native` — rebuild `better-sqlite3` if it fails to load.

## Code style

- TypeScript only; **never use `any`** (`no-explicit-any` is an eslint error).
- Prettier: no semicolons, single quotes, 2-space indent, no trailing commas,
  `printWidth` 100, always parenthesize arrow params.
- All imports at the top of the file.
- Do not add or remove comments unless explicitly asked.
- Renderer path aliases: `@` and `@renderer` → `src/renderer/src`.

## Architecture

- Three processes: `src/main` (Node/Electron), `src/preload` (bridge),
  `src/renderer` (React UI). The renderer must NOT touch Node/Electron directly.
- New capability flow: add an IPC handler in `src/main/ipc/<domain>.ts`, expose
  it in `src/preload/index.ts` as `window.api.*`, then consume it in a Zustand
  store / component.
- DB lives in `src/db`: edit `schema.ts`, run `bun run db:generate`, never
  hand-edit generated files in `src/db/migrations/`.
- Routing is a hash router (`createHashRouter`) because production loads via
  `file://`.
- Deep links: `discordrpc://import?data=<base64>` handled in
  `src/main/deeplink.ts` and wired in `App.tsx`.
- Single-instance lock is enforced in `src/main/index.ts`.

## Workflow expectations

- Always run `bun run typecheck` and `bun run lint` before declaring a task done.
- Keep changes minimal and focused; address root causes, not symptoms.
- Commits use Conventional Commits (`feat:`, `fix:`, `ci:`, `chore:`, `docs:`).
  CHANGELOG is generated by `git-cliff` — do not hand-edit `CHANGELOG.md`.

## Security

- Preserve `contextIsolation: true`, `nodeIntegration: false`, `sandbox: false`.
- Never hardcode secrets. The Discord Application ID is user-supplied data.
